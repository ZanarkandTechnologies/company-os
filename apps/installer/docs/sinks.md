# Output destinations

- Skills emit JSON. Automations render canonical local memory and reports.
- Saved answers select destinations; generated automation propagation sections
  own exact targets and authorized actions. No propagation section means no
  provider writes.
- A source binding or authenticated account never grants write authority.
- Local artifacts remain canonical; provider copies do not become a second
  memory owner.

| Output | Configuration owner |
| --- | --- |
| Local memory and reports | Generated skill and automation paths |
| Work progress or documentation comments | Daily routing choices and exact cached Work record |
| Memory/report copies | Weekly destination choices and allowed sections |
| Follow-ups and report delivery | Selected channel, recipient and instructions |

- Validate and read back local outputs before propagating them.
- Preserve unrelated provider content; check duplicates and conflicting changes.
- Missing tools, ambiguous targets or failed read-back block the affected output.
- Inspect an uncertain write before retrying; never infer a replacement target.
- Report external success only with matching provider confirmation. A local
  preview is not proof of publication.
- Connection certification retains its separate confirmation, isolation and
  cleanup gates; it does not authorize production delivery.
- Doctor remains read-only and does not exercise propagation.
